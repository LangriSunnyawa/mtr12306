# MTR-12306 铁路购票系统（Minecraft 1.20.1 · Fabric）

**b1.0.0-hotfix1** 一个基于 **MTR（Minecraft Transit Railway）** 的网页式铁路客票系统，玩法参照 12306：
浏览器里按车站/日期查车次 → 选**坐席**与**座位** → 从 **MTR 的 fares 钱包（`mtr_balance` 计分板）** 扣款出票，
再在服务器里放置**检票闸机**（模型直接沿用 MTR 的 ticket barrier），闸机只放行「本站正在检票车次」的持票旅客，
并把乘坐区间显示在屏幕上。

---

## 一、版本变化

### b1.0.0-hotfix1（当前）

**修复：闸机"不检票、可以直接穿过、反方向也不拦"**

- 原因①：闸机此前对**创造模式玩家直接放行**（当初为了搭建方便），实测时（创造模式）就表现为完全不工作 → 现在只跳过**旁观者**，创造模式同样检票。
- 原因②：**未绑定检票口的闸机只提示、不拦截** → 现在未绑定也**拒绝并推回**，不会出现"看着能用其实不检票"。
- 检测改为**双通道**：原版 `onEntityCollision` + 方块实体每 2 tick 扫描（站着不动、被推挤也可靠），并做 400ms 去重，避免重复核销。
- 增加**状态兜底**：开闸/红箭状态超时自动复位为 `closed`，避免闸机卡在开门状态导致任何人都能通过。
- 换乘闸机优先取"最近一次进站"的到达段出闸（多张联程票时更符合直觉）。

**修复：贴图重合（z-fighting）**

- 模型几何回归 **MTR `ticket_barrier` 原始 11 个元素**，只替换贴图；删除此前额外添加、与原模型共面的机柜内衬与 LED 面板。
- 指示方式改为 MTR 同款：正面箭头（白=待机 / 绿=放行 / 红=拒绝）+ 顶部小牌，六个状态变体均通过"共面且重叠"静态检查。

**新增自检工具**

- `/mtr12306 gate simulate <x> <y> <z> <玩家> <in|out> [consume] [apply]`：按真实判定流程走一遍（只读/核销，可选驱动闸机状态）。
- `/mtr12306 gate mockpass <x> <y> <z> <玩家> <in|out>`：在闸机处临时生成玩家实体跑完整流程（含开闸/推回），跑完自动丢弃，无需客户端即可验证。
- 闸机首次运行打印 `闸机 x, y, z 已开始工作（方块实体 ticker 已注册）`。

> 提示：无玩家且区块未 `forceload` 时，服务端不会 tick 该区块，闸机的扫描/定时逻辑不会运行（原版机制）；有玩家在附近时正常。

### b1.0.0（Beta 1）

- 车次**批量开行**（号段 + 停站模板 + 车底 + 首班时刻/间隔）与车次**在线修改**
- 坐席新增**城际（自由席，不对号入座）**，支持把某节车厢标注为**餐车**（不可选座）
- 票价统一 **0.1 元/公里**（`farePerKm`），接入 MTR fares 钱包扣费
- 网页**注册 + 密码登录**（昵称 + Minecraft 名称 + 密码，加盐哈希）
- 检票闸机四种模式（进站 / 出站 / 双向 / **换乘**）+ 独立创造物品栏 + **闸机配置面板**
- **强制前置 MTR 4.0.5+**；闸机只能选所在 MTR 车站的检票口

### v1.2.0

- **闸机改用 MTR 的模型**：几何 1:1 照搬 MTR `ticket_barrier`（MIT 许可），只重做了贴图
  （金属冷色调 + 面板加 12306 蓝条 + 箭头改绿/红），因此外观与 MTR 服务器里的闸机完全一致、可混用摆放。
- **状态机与 MTR 一致**：`open=closed / pending / open`，`kind=entrance（橙色底座）/ exit（绿色底座）`；
  进站闸机在 `kind=entrance` 下和 MTR 进站闸机同款，出站用绿色底座。
- **通行方式参考 MTR**：与 MTR 一样用 `onEntityCollision` 触发（玩家踏进闸机方块即检票），
  碰撞箱只有机柜（1 格空间的 1/4 边，可正常穿过），检票通过 → 指示灯变绿（向上箭头）+ 开门 40 tick 后自动复位；
  不通过 → 红色箭头 + 音效 + 把玩家推回原侧。**注意：MTR 的闸机模型本身没有栏杆，所以"拦住"是靠推回实现的。**
- **正常检票流程**：有票 → 绿箭头、提示音、标题栏显示「乘坐区间」、车票即时核销；
  无票/站不符/未开检/已用 → 红箭头 + 原因提示 + 推回。
- 闸机自动登记：区块加载（含旧存档、`/setblock`、结构生成）时会把闸机补登记到后台「闸机管理」列表。

- Minecraft **1.20.1**、**Fabric Loader** ≥ 0.15、**Fabric API**、Java 17
- **MTR 4.x for 1.20.1**（推荐；本模组对其为软依赖：没有 MTR 也能运行，只是不能一键导入车站、票价钱包退化为同名计分板）

## 四、安装

1. `dist/mtr12306-1.1.0.jar` 放入 `mods/`（双端）。
2. 安装 `fabric-api` 与 MTR（Modrinth 搜 *Minecraft Transit Railway*，选 1.20.1 Fabric 的 4.x）。
3. 启动一次服务器生成 `config/mtr12306.json`。

## 六、五分钟上手

1. **车站**：`/admin` → 「一键导入全部 MTR 车站」（或手工新增，可填站台如 `1,2,3A`）。
2. **检票口**：「检票口管理」选车站 → 名称 `A1` → 负责站台留空=全部站台。
3. **车次**：「车次管理」
   - 停靠站：车站 / 站台 / 到达 / 发车 / **天偏移** / **累计票价**（元，用于算区间票价）
   - 坐席：`SECOND 二等座 / A B C|D F / 18 排 / 1,2,3,4 车 / 倍率 1.0`，可再加一等座、商务座、无座
   - 「保存车次」后，余票、座位图、票价都自动生效
4. **闸机**：`/give @s mtr12306:ticket_gate`，成排摆放（相邻自动继承检票口），
   管理员右键 → 选检票口 + 模式（**放置时面向站台一侧**，闸机正面=出站方向）。
   外观与 MTR 自带的 ticket barrier 完全一致（进站橙色底座 / 出站绿色底座），可以和 MTR 的闸机混排。
5. **充值**：MTR 售票机/票价闸机充值，或 `/mtr12306 balance <玩家> <金额>`。
6. **玩家购票**：网页 → 「登录」→ 游戏内先 `/ticket login` 拿验证码 → 登录 →
   查车次 → 点坐席 → 选车厢/座位 → 确认支付（从 fares 钱包扣款）。
7. **检票**：到检票时间走过闸机，闸门抬杆、屏幕显示 `乘坐区间：中央车站 → 西港站（00:15-00:33）· 二等座 03车 3C`。

> 想马上演示？管理员 `/mtr12306 boarding open <车次> <车站id> 15` 立即开检 15 分钟。

## 七、闸机与检票规则

- **模型与状态**：沿用 MTR 的闸机模型；方块状态 `open = closed / pending / open`，`kind = entrance / exit`。
  `closed` 待机（无箭头）→ `pending` 拒绝（红色箭头，1.5 秒）→ `open` 放行（绿色箭头，40 tick 后自动回到 `closed`）。
- **碰撞箱**：与 MTR 一致，只有机柜那四分之一格是实心的（`createCuboidShape` 12..16 半边），
  玩家可以正常走进闸机格；**拦人依靠"推回"**：拒绝时把玩家传送回进入前那一侧并清零速度。
  卡在机柜里（异常情况）也会被推出去。
- **触发方式**：与 MTR 相同，用方块的 `onEntityCollision`，玩家踩进闸机所在格即检票；开门期间不重复检票（防尾随刷票）。
- **配置方式**：拿 **闸机配置面板** 右键闸机（需要 OP 权限）才会打开配置菜单；直接右键只提示当前绑定。
- **检票口限定**：配置菜单只列出闸机所在 **MTR 车站** 对应的检票口（按车站名匹配，可用后台「一键导入 MTR 车站」保持同名）；
  不在任何 MTR 车站范围内时列表为空并提示，服务端也会拒绝跨站绑定。
- **四种模式**（对应创造模式物品栏里的四个闸机物品）：
  - **进站**：校验车票 → 放行并核销；无票推回。
  - **出站**：只放行从站台侧走出，并记录车票「已出闸」。
  - **双向**：进站查票；出站要求「今日已有已检票车票」。
  - **换乘**：一次通过完成「上一段出闸」+「接续车次检票」，接续车次需在检票窗口或
    `transferWindowMinutes`（默认 30 分钟）内；两段区间会分别显示在屏幕上。
- **方向**：闸机 `FACING`（放置时玩家朝向）为**站台侧**。
  - `ENTRY`（进站检票）：只处理「背面 → 正面」，校验车票后开闸；从站台侧过来不响应。
  - `EXIT`（出站放行）：只处理「正面 → 背面」，不查票直接开闸。
  - `BOTH`（双向）：进站校验车票；出站校验「今日已有已检票车票」，否则拦下。
- **通过条件**（全部满足）：车票未使用 · 乘车日期=今天 · 出发站=本站 · 该车次**此刻在本检票口检票中** ·
  车票区间覆盖该站 · 检票口负责的站台包含该车次站台。
- **失败原因**会明确显示（无票 / 站不符 / 未开检 / 已检票使用 / 检票口停用 / 闸机未绑定检票口）。
- 车票在**开闸瞬间**标记为「已检票」，一票一次；创造/旁观模式不受限（方便建造）。
- 开检时全服播报：`【检票公告】G1234 次（中央车站 00:15 开，站台 1）开始检票，检票口：A1…`

## 八、票价与 MTR fares 钱包

- 区间票价 = （到达站累计票价 − 出发站累计票价）× 坐席倍率 × 全局倍率（未填累计票价时按每站 `farePerStopFallback` 估算）。
- 扣款走 MTR 自带计分板项目 **`mtr_balance`**（标题 `Balance`），与 MTR 售票机、票价闸机**共用同一余额**；
  项目不存在时模组会按相同名称与标题自动创建（无 MTR 时也可用）。
- 购票：余额不足直接拒绝并提示所需金额；退票：自动原路退回。
- 管理员工具：`/mtr12306 balance <玩家> [金额]`，后台「票价钱包」卡片（填负数=扣款）。

## 九、命令

管理员（权限等级 2）：

```
/mtr12306 help
/mtr12306 web start|stop|info
/mtr12306 station add <名称> [站台1,站台2] | list | remove <id>
/mtr12306 checkpoint add <车站id> <检票口名> [站台…] | list | remove <id>
/mtr12306 service list | remove <车次>          # 车次/坐席/票价在网页后台配置
/mtr12306 gate bind <检票口id> [ENTRY|EXIT|BOTH] | unbind | info
/mtr12306 boarding list | open <车次> <车站id> [分钟] | close <车次> <车站id>
/mtr12306 ticket buy <玩家> <车次> <出发站id> <到达站id> [坐席码]
/mtr12306 ticket list
/mtr12306 balance <玩家> [充值金额]
/mtr12306 login <玩家>                          # 为其签发网页登录验证码（控制台可用）
```

所有玩家：

```
/ticket              我的车票与余额
/ticket list         同上
/ticket login        获取网页登录验证码（6 位，5 分钟有效）
```

## 十三、常见问题

**Q：闸机挡不住人？** 这是与 MTR 一致的设计：MTR 的闸机模型没有栏杆，只有机柜有碰撞箱，拒绝通行时靠**推回**拦人。
如果你需要"实体墙"式的闸机，请使用 v1.1.0 的自定义模型版本（那版关闸时整格实心），或自行把模型换成带栏杆的版本。

**Q：一直说"未绑定检票口"？** 管理员右键闸机选检票口；成排放置时后续方块会自动继承。

**Q：余额一直 0？** 需要先用 MTR 的售票机/票价闸机充值，或用 `/mtr12306 balance <玩家> 100`。

**Q：玩家说浏览器登录不上？** 让他在游戏里输入 `/ticket login`，聊天栏会给出 6 位验证码（5 分钟内有效，输错 5 次作废）。

**Q：闸机配置里看不到检票口？** 说明闸机不在 MTR 车站范围内，或本系统的车站没有与 MTR 车站同名。
先在 MTR 里划好车站，再用后台「一键导入全部 MTR 车站」保持名称一致。

**Q：换乘闸机不认票？** 需要①上一段车票已检票进站且尚未出闸；②本站有已购的接续车票，
并且处在接续车次的检票窗口或 `transferWindowMinutes` 内。

**Q：能不用客户端模组吗？** 不行：闸机是方块（需要客户端模型/贴图），且设置界面与网络包在客户端。要把闸机改成"区域式"纯服务端方案需要另做版本。
